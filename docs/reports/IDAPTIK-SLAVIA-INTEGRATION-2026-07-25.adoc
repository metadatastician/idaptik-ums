== Dependency graph

[source,text]
----
UMS editor/source
  -> isolated profile compiler
  -> game-owned versioned contract/package
  -> game-owned loader and runtime
  -> selected Enaction facilities
----

`just architecture-check` rejects reverse Enaction-to-UMS dependencies,
game-to-UMS runtime/UI dependencies, UMS-to-game-runtime Cargo links, and
IDApTIK/Slavia profile imports in either direction.

== Contract ownership and artifacts

IDApTIK owns scenario, room, floor, door, camera, hide-spot, prop, actor,
objective, action, tuning, difficulty, scoring, grounded-network,
physical-effect, snapshot and package-loading semantics.

Introduced or exposed artifacts:

* IDApTIK `contracts/idaptik/v1/contract.json`
* IDApTIK `contracts/idaptik/v1/package.schema.json`
* IDApTIK authoritative Ghost Lobby contract fixture
* IDApTIK `idaptik-core::package` loader and headless runner
* UMS `ums-profiles` generic validator/compiler
* UMS IDApTIK Ghost Lobby profile source
* UMS Slavia v1 profile and Zone A / Border Path fixture

UMS does not re-declare `ScenarioDefinition`, `LevelData`, game action enums or
objective enums. It reads the sibling game's published metadata and fixture.

== Exact IDApTIK round trip

[source,text]
----
profiles/idaptik/v1/ghost-lobby.ums.json
 -> ums-profile compile-idaptik
 -> temporary idaptik-package/v1 JSON
 -> idaptik-core::load_package (same bytes)
 -> ScenarioDefinition::validate
 -> GhostLobbySim
 -> PivotOpened + UplinkAction(Camera) + CameraPinged
 -> RuntimeSnapshot v2
 -> GhostLobbySim::restore
 -> replay of the post-snapshot command tail
 -> byte-structural event and final-snapshot equality
 -> RoundTripResult consumed by the just gate
----

The fixture carries the existing five-room Ghost Lobby, four traversal doors,
three cameras, hide spots, props, Billy, a non-runtime-bound civilian roster
entry, objectives with service-exit/laundry alternatives, a grounded bridge
pivot, and a camera network action producing the physical feed-loop effect.
The package guarantee requires the deterministic seed, snapshot v2 and the
three boundary events.

Run from UMS:

[source,sh]
----
just roundtrip-idaptik
----

== Enaction evidence

Actually proven in IDApTIK:

* endpoint-exact interpolation;
* the inline `DoubleBuffer`;
* continuous position/door blending;
* discrete facing reads;
* commit-then-snap restart behaviour.

Proven by comparison tests but not adopted:

* healthy 60 Hz `FixedStep` accounting;
* hostile/non-finite elapsed-time policy;
* accumulator reset at a discontinuity.

New and not yet run in a game:

* `enaction-cognition`, the generic six-domain causal trace seam.

No IDApTIK timing code was replaced. IDApTIK still uses Bevy's fixed clock.

== Bounded cognitive-affective-conative seam

The IDApTIK package slice emits a deterministic, serialisable trace:

[source,text]
----
camera signal failed
 -> possible interference appraised (epistemic, not confirmed)
 -> anxiety changed (affective)
 -> verification goal raised (conative)
 -> verify-feed behaviour selected
 -> security-team protection context recorded
----

IDApTIK stores game-specific guard stages. Enaction stores game-neutral domains.
They are not duplicate enums; a future explicit adapter may map between them.

== Slavia profile coverage

The Zone A / Border Path fixture contains Anya, Donna, birds, the unstable
bridge, a receptive shrine, one Rift disturbance and a cooperative completion
condition. It covers quickening, settling, natural response according to the
recipient's own nature, bridge stabilisation, shrine interaction,
environmental receptivity, place memory, moral/world marking, Rift disruption,
inversion, corruption and severance, plus the cost of either heroine's absence.

The validator is generic and an isolation test scans UMS Core for profile
vocabulary. Slavia does not load the package in this pass.

== Compatibility and migration concerns

The v1 IDApTIK envelope accepts exactly game version `0.1.0`, profile `1.0.0`,
Ghost Lobby scenario format v2 and snapshot format v2. This is deliberately
strict. Any incompatible scenario or snapshot change needs a new contract
version or an IDApTIK-owned migration. The current fixture references the
authoritative game scenario artifact, so repository-relative orchestration
assumes the four sibling checkouts remain together under `meta-repos`.
